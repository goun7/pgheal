How it works

Three steps, no agents on your database, nothing leaves your network.

Observe

Reads top statements from pg_stat_statements and catalog statistics through a strictly read-only connection (default_transaction_read_only=on, lock_timeout=1s).

Prove

Generates index candidates (B-tree, GIN, BRIN), simulates them with HypoPG hypothetical indexes in the live planner, and keeps only plans with real cost wins.

Deliver

Opens a shadow branch and pull request with the migration for your dialect — plus unused-index cleanup candidates after a 30-day observation window.

Quick start

Requires Node 20+, a PostgreSQL with pg_stat_statements, and HypoPG for proof mode.

# install
$ npm i -g pgheal

# check your environment is ready
$ pgheal doctor

# dry-run: prove wins and print the report
$ DATABASE_URL=postgres://app@db/prod pgheal scan

# open the PR
$ GITHUB_TOKEN=… GITHUB_REPO=acme/api pgheal scan --write

See it work

From zero to a proven recommendation on the bundled demo database — no signup, your terminal only.

# run the whole demo stack (Postgres 18 + HypoPG + 500k-row workload)
$ git clone https://github.com/goun7/pgheal && cd pgheal
$ docker compose up -d --build

# watch it prove a real speedup
$ DATABASE_URL=postgres://pgheal:pgheal@localhost:5433/demo pgheal explain \
    "SELECT * FROM orders WHERE user_id = 42 AND status = 'paid' ORDER BY created_at DESC"
# Gather Merge 8465.9 → Bitmap Heap Scan 35.2  (99.6% cost reduction)
